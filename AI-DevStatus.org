* Key Design Decisions

  - *=webVd_update= does NOT enable*: writing the config file and enabling it are
    separate operations, matching NGINX's own sites-available/sites-enabled idiom.
    This allows a config to be staged before activating it.
  - *=webVd_enable= is idempotent*: checks for existing symlink before creating;
    always runs =nginx -t= and reload regardless.
  - *=webVd_disable= leaves =sites-available/= untouched*: only the symlink is
    removed, so the config is preserved for re-enabling.
  - *=webVd_update= uses a tempfile + =sudo cp=*: writing directly to
    =/etc/nginx/sites-available/= requires root; the pattern is write to a
    user-owned tempfile then =sudo cp= it into place (same approach avoids
    =sudo tee= or heredoc complexity).
  - *=examples_csu= is a plain =@cs.track def= function* (not =cs.Cmnd= class):
    class form triggers =AttributeError: 'Namespace' object has no attribute 'perfName'=
    via the CS framework's =ro.py= layer. This is the same lesson learned in
    =capDns_csu.py= — must use function form.
  - *Existing =djangoProc_*= / =reactProc_*= files kept*: they are a separate
    gunicorn/Django/React capability, not facter leftovers. Out of current scope
    but not harmful.
  - *=setup.py= managed by user via =pypiProc.sh=*: Claude does not touch =setup.py=.
